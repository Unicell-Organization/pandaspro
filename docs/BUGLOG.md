## BUG-002 · P1 · 已修复

**标题**　cpdtab2 系列字段数超过两个又没写 `___` 时，多出来的字段被静默丢掉，返回一张看起来正常但少了一维的表

**发现**　2026-10-08 · 核对已删除的 `cpdt2p_` 与 `cpdtab2_` 的差异时，照旧写法 `cpdtab2_region__dept__grade` 实际跑了一遍

**引入**　cf19bc8（2025-10-15，multindex support）

**影响面**　`cpdtab2_`、`cpdtab2s_`、全部六个 `cpdtab2pct*` / `cpdtab2spct*`、以及所有 `cpdtab2{agg}_`。
触发条件：不含 `___`，计数 / 百分比写了 3 个及以上字段，聚合写了 4 个及以上字段。
不报错、不告警，结果是合法的 region × dept 表，只是 grade 没了。

**成因**
1. 表层——不含 `___` 的路径固定取 `matched[0]` 当行、`matched[1]` 当列，其余下标没人读。
2. 中层——cf19bc8 之前这里是 `pivot_index, pivot_columns = _parse_and_match(...)`，字段数不对会在解包时直接炸；改成按下标取之后，「字段数不对」从报错变成了静默截断。同一次提交删掉了 `cpdt2p_`（它的约定正是「全写 `__`，最后一个当列」），于是老用户的肌肉记忆恰好落在这条截断路径上。
3. 根层——属性名解析没有「每个字段都必须被用到」的约定。解析结果只校验下限（至少 2 个），不校验上限，多余输入没有去处也没有报错点。

**为何测不出**　cpdtab2 计数路径此前没有任何测试；而且返回值是结构完全合法的交叉表，就算有「能跑通、有 Total」这类断言也照样通过。

**若不处理的代价**　拿错的表去做分析或导出，数字加总仍然对得上（Total 没变），几乎不可能从结果反推出少了一个维度。

**修复**　修根层：`tools/tab2.py` 的 `parse_pivot_fields_from_attr` / `parse_agg_fields_from_attr` 对不含 `___` 的写法校验字段数上限，超出即报错，并在报错里给出带 `___` 的正确写法。四个内联分支改为统一走这两个解析函数，不再各自按下标取。

**验证**　`tests/core/test_tabops.py::test_extra_fields_without_separator_raise_instead_of_being_dropped`（计数 / 小计 / 百分比 / 聚合四种前缀）；两个字段的正常写法输出不变（`test_count_tab_unchanged`）。

**待跟进**　已发布的 1.0.2 等旧版本仍有此问题，修复随 1.2.0 发布。

**教训**　把「解包」换成「按下标取」会把数量校验一起删掉；解析用户输入时，没被消费的部分必须报错。

## BUG-001 · P1 · 已修复

**标题**　`cpdtab2sum_` / `cpdtab2std_` 被当成「带小计」分支处理；配 `___` 时前缀多切一个字符，报字段 `'egion'` 找不到

**发现**　2026-10-08 · 跑 `cpdtab2sum_region___grade__salary` 时报 `Missing: {'egion'}`

**引入**　cf19bc8（2025-10-15，multindex support），新增 `item.startswith('cpdtab2s')` 分支时

**影响面**　聚合名以 s 开头的两个：sum、std。
- 配 `___`：直接报错，无法使用（`cpdtab2mean_` 等不受影响，所以看起来像是偶发）。
- 不配 `___`：能出结果，但走的是小计分支，合计行列叫 `Total` 而其他聚合叫 `All`。

**成因**
1. 表层——分发链先判 `startswith('cpdtab2s')` 再判 `startswith('cpdtab2')`，`cpdtab2sum_` 命中前者；前缀长度按 `'cpdtab2s' + 'sum' + '_'`（12）算，实际前缀是 11 个字符，第一个字段被切掉首字母。
2. 中层——「小计」的标记是单个字母 s，而聚合函数名本身可以以 s 开头。`startswith` 逐级判断无法区分「s + um」和「sum」；真正能区分的只有把「可选的 s + 聚合名 + 下划线」作为一个整体去匹配。
3. 根层——修饰项全部靠往前缀里追加字母来表达，前缀之间没有分隔符，也没有一张表声明全部合法前缀。每加一个修饰项，就和已有前缀多一组潜在的前缀包含关系，只能靠分支顺序碰运气。

**为何测不出**　聚合路径没有测试；手工试的时候通常用不带 `___` 的写法，那条路径恰好能出结果，只是合计的名字不同。

**若不处理的代价**　报错信息指向「字段 egion 不存在」，会先去怀疑列名拼写和数据，而不是前缀分发；同时 mean 正常、sum 不正常，容易被当成数据问题。

**修复**　修中层 + 缓解根层：`tools/tab2.py` 新增 `detect_cpdtab2_agg`，用一个正则把 `cpdtab2(s?)(聚合名)_` 整段匹配，同时得到聚合名、是否小计、前缀长度；`frame.py` 里两个聚合分支合并为一个。之后新增的展示选项（nototal / tdiff / tratio / tsort）不再往前缀里加字母，而是接在结果后面，不再扩大前缀冲突面。

**验证**　`test_detect_cpdtab2_agg_s_prefixed_functions`；`test_agg_with_triple_underscore_matches_plain_form` 对 sum / std / mean / min / max / median / var 逐个比对带 `___` 与不带的结果一致；`test_agg_subtotal_with_s_prefixed_function`。

**待跟进**　sum / std 的合计历史上一直叫 `Total`、其余聚合叫 `All`，这次保持原样（`LEGACY_TOTAL_AGGS`），是否统一待定。
`first` / `last` 在 pandas 3.0 下因 `pivot_table(margins=True)` 自身不支持而报错，与本条无关；同一次提交里改为不带合计（挑一行不是汇总，合计本来没有意义）。

**教训**　用前缀字母表达修饰项时，任何新字母都可能是某个已有名字的开头；要么整段匹配，要么别往前缀里加。
